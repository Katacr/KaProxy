# 升级与迁移

## 升级 KaProxy

1. 关闭代理服务器。
2. 备份 KaProxy 数据目录中的 `config.yml` 和 `lang/` 文件夹。
3. 将旧 KaProxy JAR 移出 `plugins` 文件夹。
4. 放入新版本 KaProxy JAR。
5. 启动代理并查看启动日志。
6. 执行 `/kaproxy status` 检查模块状态。
7. 使用两个测试账号验证跨服公会消息和跨服传送。

一般情况下无需删除原有配置。如果新版本增加配置项，可参考新版默认配置手动补充。

## 从 KaGuildsProxy 迁移

KaProxy 已提供现有 KaGuilds 所需的跨服兼容功能。

迁移步骤：

1. 关闭代理。
2. 删除或移走代理端的 `KaGuildsProxy.jar`。
3. 安装 KaProxy。
4. 保留子服中的 KaGuilds 和原有 `proxy: true` 设置。
5. 确认所有子服仍连接同一个 MySQL 数据库。
6. 启动并测试公会聊天与跨服在线状态。

旧插件备份可以保留，但旧 JAR 不能继续放在正在运行的代理 `plugins` 目录中。

## 从单服 KaTpa 切换到跨服

1. 在代理端安装并启用 KaProxy 的 Tpa 模块。
2. 在所有相关子服安装相同兼容版本的 KaTpa。
3. 启用每个子服的 KaTpa 代理选项。
4. 建议将各子服切换到同一个 MySQL 数据库。
5. 对齐各子服的请求超时、吟唱和冷却设置。
6. 在不同子服之间测试 TPA 与 TPAHERE。

## 回退

需要回退时：

1. 关闭代理。
2. 恢复上一版本 JAR 和对应配置备份。
3. 确认代理目录中只存在一个负责 KaGuilds 跨服转发的插件。
4. 启动代理并重新测试。

代理重启会清除尚未完成的跨服传送请求，建议在在线人数较少时进行升级或回退。
